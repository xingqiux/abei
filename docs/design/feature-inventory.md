## 二、逐域细节

### 1. 账户

**Firefly 有什么**：五类账户（资产 asset、支出方 expense、收入方 revenue、负债 liabilities、现金 cash）。资产账户还有角色（默认/储蓄/信用卡）。字段含开户余额与日期、虚拟余额、币种、IBAN、账号、备注、经纬度、是否计入净值、信用卡还款日、负债类型（贷款/债务/按揭）、负债方向、利率与计息周期。另有 `GET /accounts/{id}/attachments`、`/piggy-banks`。

**web 现状**：`AccountsPage` 按类型分 tab、无限滚动、归档（走 DELETE）；`AccountDialog` 新建与编辑；`AccountDetailPage` 余额面积图 + 该账户交易无限流。`AccountInput` 已覆盖大部分字段。

**缺口**：IBAN / BIC / 经纬度 / 虚拟余额没有；账户附件与账户下储蓄罐没接；列表没有搜索和排序；归档与删除在 UI 上是同一个动作（文案写「归档」，实际调 DELETE）。

**建议**：保留。补虚拟余额（信用卡额度要用）；IBAN/经纬度可以直接不做。**归档与删除的语义要澄清**——Firefly 的 DELETE 是真删（连带交易），这是目前 UI 的一个隐患。

### 2. 交易

**Firefly 有什么**：交易组（TransactionGroup）下挂拆分（TransactionJournal）。类型：withdrawal 支出 / deposit 收入 / transfer 转账 / opening balance 开户余额 / reconciliation 对账调整。每条拆分可带：分类、预算、订阅、标签、备注、附件、外币金额、内部引用、外部 ID、外部 URL、经纬度、已对账标记、关联储蓄罐。交易组之间可以建链接（退款/关联/复制）。

**web 现状**：交易页按日分组 + 当日小计 + 类型 tab + 无限加载；行点开是详情弹窗；记一笔弹窗（顶栏与 `n` 键）；编辑（含多拆分编辑器）；删除；附件上传下载。

**缺口**：
- 没有筛选。只有「全部/支出/收入/转账」四个 tab，没法按账户、分类、标签、金额区间、关键词过滤。
- 没有批量选择与批量操作（Firefly 有 `POST /data/bulk/transactions`）。
- 没有键盘操作（上下移动、快速改分类）。
- 创建时不能填内部引用/外部 URL/经纬度/储蓄罐关联。
- 没有交易链接界面。
- 列表不是表格，是自定义行组件，没有列对齐、没有密度切换、没有粘性日期头。

**建议**：这是重做 UI 的核心页，见设计方案。

### 3. 预算

**Firefly 有什么**：预算（Budget）+ 期限额度（BudgetLimit，一个预算可以有多个时间段的额度）+ 自动预算（AutoBudget：固定/滚动/累加三种模式，按周期自动生成额度）+ 可用预算（AvailableBudget，某周期内可分配总额，**只有 GET 没有写接口**）+ 预算下交易钻取 + 未编入预算的交易。

**web 现状**：`BudgetsPage` 列出预算与用量条，可新建（含首个限额）、改名、删、改限额。

**缺口**：自动预算完全没有（这是 Firefly 里最省事的功能）；可用预算没有；预算下钻交易没有；`GET /budgets/transactions-without-budget` 没接。

**建议**：保留并补自动预算。注意可用预算 API 只读，要用得走老前端逻辑或直接不做。

### 4. 订阅（Bills）与 8. 定期交易（Recurrences）

这两个在 Firefly 里是**不同的东西**，容易混：

| | 订阅 Bills | 定期交易 Recurrences |
|---|---|---|
| 作用 | 声明「我每月大概会付一笔 X 元的宽带费」，用来**匹配**已发生的交易并提醒未付 | 声明「每月 1 号自动**生成**一笔 100 元的交易」 |
| 会不会造数据 | 不会 | 会（cron 自动创建） |
| 字段 | 金额区间、周期、跳过几期、匹配规则 | 完整交易模板 + 重复规则（每日/每周/每月/每年/第 n 个星期几） |
| API | 8 个（另有 `/subscriptions` 是同一套的别名） | 7 个 |
| web 现状 | 只读一行，没有增删改 | 列表 + 手动触发，没有增删改 |

**建议**：账单收件箱已经在做「从邮箱把真实账单捞进来」，**订阅（Bills）的提醒价值和它重叠**。定期交易适合房租、工资这种固定且邮箱里没有凭证的。需要你拍板留哪个。

### 5. 储蓄罐

**Firefly 有什么**：储蓄目标，挂在资产账户上（新版支持多账户），有目标金额、目标日期、存取事件流水、可分组。

**web 现状**：只读一行。

**建议**：❓ 个人记账里这是「有也行没有也行」的功能。你要是不用存钱目标，直接删掉这个 tab。

### 6. 分类与标签

**Firefly 有什么**：分类是单层的（没有父子层级），标签可以带日期、描述、经纬度。两者都能下挂交易和附件。

**web 现状**：设置页的「参考数据」面板可以列出、新建、编辑、归档分类与标签。✅

**缺口**：不能看某分类下的交易；标签的日期/描述字段没做。

### 7. 规则引擎

**Firefly 有什么**：规则组 → 规则 → 触发器 + 动作。触发器几十种（描述包含、金额大于、账户是、日期在……），动作也几十种（设分类、设预算、加标签、改描述、删除、转换类型……）。支持表达式校验、按日期范围测试（看会命中哪些交易）、手动执行。还能挂在「新建交易时自动跑」。

**web 现状**：设置页「自动化」面板能列出规则组与规则、测试（看命中数）、执行。**不能创建、不能编辑触发器和动作**。

**建议**：❓ 这是本次最大的一个方向选择。规则引擎的编辑界面工作量很大（触发器/动作两套动态表单），而你的主线是 AI 归类。两条路：
- A：不做规则编辑界面，规则用 CLI/AI 生成，界面只保留「测试 + 执行 + 开关」。
- B：做完整规则编辑器，AI 只负责「建议规则」，人来确认。

### 9. 报表

**Firefly 有什么**：老前端有六种报表页（默认、审计、分类、预算、标签、双向），**这些是服务端渲染的，随前端一起删了**。API 侧只剩：
- `insight/*` 25 个端点：支出/收入/转账 × 按账户/分类/预算/订阅/标签/无分类/无预算/总额。
- `chart/*` 4 个：账户余额总览、余额对比、预算总览、分类总览。
- `summary/basic`：一段时间的收支净值汇总。

**web 现状**：报表页有 8 个排行（分类支出、收入来源、账户流出、标签支出、预算支出、未分类、未编入预算、转账流向）+ 概览卡。

**缺口**：没有期间对比（本月 vs 上月）、没有趋势线、没有净值曲线、没有现金流桑基图、没有审计式的逐日余额表。

**建议**：报表页重做。数据都在 insight 里，缺的是组织方式。

### 10. 搜索

**Firefly 有什么**：一套查询语言，`GET /search/transactions?query=`，支持 `amount:>100`、`category:餐饮`、`source_account:招商`、`date_after:2026-01-01` 等几十个操作符；另有 `search/transactions/count` 和 `search/accounts`。

**web 现状**：只有命令面板里的模糊搜索（搜交易描述与账户名），没有搜索结果页，没有操作符提示，搜索结果不能筛选和导出。

**建议**：把搜索做成一等公民——交易页的筛选栏直接翻译成查询语言，搜索结果页复用交易列表。

### 11. 自动补全

17 个端点：账户、账单、预算、分类、币种、对象组、储蓄罐、定期交易、规则、规则组、订阅、标签、交易、交易类型。web 用了 4 个。按需补即可，成本很低。

### 12. 多币种与汇率 ⛔

**Firefly 有什么**：币种 CRUD、启用/停用、设主币种、每账户币种、交易外币金额、汇率表 CRUD（12 个端点）、按日期/按币种对批量设汇率。

**web 现状**：设置页只读列出币种；记一笔的多拆分编辑器里能选币种。

**建议**：**你说了不做多国家，这块是最大的一块删除项。** 具体做法：
- 前端所有币种选择去掉，写死 CNY。
- 汇率、币种管理、外币金额输入全部不做。
- 但**后端 Firefly 的币种字段不能删**（数据模型强依赖），只是界面不暴露。
- 保留的：金额显示时的 `¥` 符号。

风险：将来你要是记港币/美元消费（境外消费、美元订阅），就要回头补。需要确认。

### 13. Webhooks ⛔

Firefly 能在交易创建/更新/销毁时向外发 HTTP 请求，带投递重试与消息记录（13 个端点）。

**建议**：不做界面。AI 主线要联动的话，CLI 直接调 API 比 webhook 简单。后端保留不动。

### 14–16. 数据

- **导出**：11 种类型导出 CSV，web 已有 ✅。
- **清理**：`DELETE /data/purge`（真删软删除的记录）、`DELETE /data/destroy`（按类型清空）。⛔ 不做界面，太危险，留 CLI。
- **批量改**：`POST /data/bulk/transactions` 能批量改分类/预算/标签。⬜ 建议做，配合交易页的批量选择。

### 17. 附件

Firefly 能给交易、账户、预算、分类、标签、订阅、储蓄罐都挂附件。web 只做了交易附件（上传/改名/下载/删除）。

**建议**：保持现状。账单 PDF 挂在交易上是对的位置。

### 18. 交易链接 ❓

`link-types`（6 个端点，可自定义链接类型）+ `transaction-links`（5 个端点）。默认类型有「相关」「退款」「付款」「重复」。

**建议**：唯一有实际价值的场景是**退款关联**（买了又退，两笔要能对上）。你说了算：做退款关联，还是整块删掉。

### 19. 对象组 ⛔

只是给订阅和储蓄罐分组用的。如果订阅和储蓄罐都精简掉，这个自然没了。删。

### 20. 偏好与配置

- **preferences**（4 个端点）：用户级 KV 存储。web 已经用它存日期范围偏好 ✅。将来存密度、主题、列配置都靠它。
- **configuration**（3 个端点）：管理员配置，单用户模式、是否允许注册、是否强制 2FA 之类。⛔ 单人自托管，改 .env 就够，不做界面。

### 21. 用户与用户组 ⛔

`users` 5 个端点（管理员增删改用户）、`user-groups` 3 个端点（多用户财务域，Firefly 正在做的多租户）。单人使用，全删。

### 22. 系统

- `about` / `about/user`：版本与当前用户 ✅ 已用。
- `POST /tokens`：自建的 PAT 签发 ✅ 设置页已用。
- `cron/{cliToken}`：定时任务入口（定期交易生成、订阅提醒）。没有界面，也不需要。
- `health`：健康检查，给容器编排用。
- `batch/finish`：批处理收尾。

### 23. 账单收件箱（自建，7.6k 行）✅

12 个 bill-tasks 端点 + 6 个 bill-inbox + 3 个 bill-statement-rows + 1 个 bill-artifacts。

**web 现状**：渠道卡、任务列表、明细行审阅与行内编辑、拆分行、解压密码提交、重试、干跑与真实入账、忽略、凭证与事件面板、同步与清理、设置对话框。覆盖较全。

**缺口**：`POST /bill-tasks/archive` 与 `POST /bill-tasks/{id}/archive`（归档）没接；`GET /bill-tasks/{id}` 单条详情没接（列表里已有数据，影响不大）。

### 24. 按天对账（自建）✅

日汇总 + 标记已对账 + 生成调整交易。已实现，已实测。已知遗留：调整方向只能往下（减少余额），要加「增加/减少」切换。

### 25. 账号自身 ❓

Firefly 前端删掉后，**登录、注册、改密码、2FA、OAuth 客户端管理全都没有界面了**。目前靠 PAT 顶着，PAT 由 `POST /api/v1/tokens` 或 artisan 命令签发。

需要决定：要不要在设置页做一个最小的「改密码 / 看 2FA 状态 / 撤销令牌」界面。不做也能活（artisan 命令兜底），但令牌泄漏时你连撤销的地方都没有。

## 三、明确建议删掉的（不接界面）

| 功能 | 端点数 | 理由 |
|---|---|---|
| 多币种管理 + 汇率 | 15 + 12 | 只记 CNY |
| Webhooks | 13 | CLI 直连 API 更直接 |
| 用户管理 + 用户组 | 5 + 3 | 单人使用 |
| 管理员配置 | 3 | 改 .env |
| 数据销毁 / 清空回收站 | 2 | 危险，留 CLI |
| 对象组 | 6 | 只服务于订阅与储蓄罐的分组 |
| 币种下的关联查询 | 约 8 | 随多币种一起删 |

合计约 67 条端点直接不进前端，覆盖率的分母因此从 201 降到约 134。

## 四、已拍板（2026-08-05）

细节与实现要点见 `redesign-decisions.md`。

| 问题 | 决定 |
|---|---|
| 订阅 vs 定期交易 | 合并成一个概念「订阅」，**底层用 Recurrence**（有交易模板 + 手动触发），Bills 与 subscriptions 别名整块不接 |
| 储蓄罐 | 删，连带对象组 |
| 规则引擎 | 整块不进界面（后端仍会执行，需先清查存量规则） |
| 交易链接 | 不做 |
| 多币种 | 只出 CNY，外币按入账人民币额记 |
