# abaku-web 重构：已定决策与实现要点

定稿日期：2026-08-05。配套文档：`feature-inventory.md`（Firefly 全功能对照表）、
`../implementation-plan.md`（分阶段实施计划与验证结论）。
名字与 logo 见第八节，已定为 Abaku / 算珠。

---

## 一、功能取舍（已定）

### 1. 订阅与定期交易合并成一个概念：「订阅」

**你要的流程**：订阅提醒 → 点一下 → 自动创建一笔交易。

**实现方式**：界面上只有「订阅」这一个概念，**底层用 Firefly 的 Recurrence（定期交易），不用 Bill**。

理由是 Firefly 这两个模型的能力不对称：

| | Bill（订阅） | Recurrence（定期交易） |
|---|---|---|
| 有交易模板吗 | **没有**。只有名称、金额区间、周期、跳过、备注 | **有**。类型、来源/目标账户、金额、描述、分类、预算、标签全都有 |
| 能生成交易吗 | **不能**，只能匹配已存在的交易 | **能**，`POST /recurrences/{id}/trigger` |
| 下次到期日 | 有 `next_expected_match` | 有 repetitions，可算下次日期 |

Bill 没有账户和分类模板，"点一下生成交易"就无从谈起——只能另存一份映射表，是脏做法。Recurrence 天生就是模板 + 触发。

**因此**：`bills`（8 个）与 `subscriptions`（8 个别名）两组接口整块不接。

**实现要点**：
- 一级页面「预算」下加「订阅」tab，列出所有 recurrence 及下次到期日。
- 「今天」页的待办区显示「本月待付 N 笔」，点进订阅列表。
- 每行一个「记这一笔」按钮 → `POST /recurrences/{id}/trigger`，成功后跳到新建的交易。

**待验证（实施前先用真实数据验一遍）**：
1. `active=false` 的 recurrence 还能不能手动 trigger。如果不能，就得让它保持 active 但阻止自动生成。
2. Firefly 的 cron 会自动生成 active 的 recurrence。我们要的是手动触发，得确认怎么关——是靠不跑 cron，还是靠 `repeat_until` / repetitions 配置。
3. `trigger` 的 `date` 参数语义（是"按这个日期生成"还是"生成截至这个日期的所有期次"）。

### 2. 储蓄罐：删

连带对象组（object-groups，它只服务于储蓄罐和订阅的分组）一起删。省 8 + 6 个接口和一个 tab。

### 3. 规则引擎：整块不进界面

`rules`（8）+ `rule-groups`（8）全部不接，设置页的「自动化」面板去掉规则部分。

**注意**：删的是界面，**Firefly 后端的规则引擎仍然会在新建交易时执行**。如果数据库里已经存有规则，它们会继续生效且没有地方能看到。实施时要先查一遍现有规则，要么全部禁用，要么明确知道留了哪些。

### 4. 交易链接：不做

`link-types`（6）+ `transaction-links`（5）不接。退款按普通收入记，靠备注或标签自己认。

### 5. 只记人民币

界面上不出现任何币种选择。外币消费按银行实际扣的人民币金额记。

- 币种管理（15）、汇率（12）两组接口不接。
- 设置页的币种只读列表删掉。
- **但后端字段不能省**：建账户和建交易时仍要传 currency，前端写死 CNY。

### 6. 账户「归档」改成真归档

现在按钮写「归档」实际调 `DELETE`，Firefly 会连带处理该账户下的交易。改成：

- 列表里的「归档」= `PUT /accounts/{id}` 设 `active=false`，账户从默认列表隐去，数据全在。
- 列表加「显示已归档」开关。
- 真删除移到账户详情页底部的危险区，要求输入账户名确认。

### 7. 账号：只做令牌列表 + 撤销

**这里有个接口缺口要先补**：我们只加了 `POST /api/v1/tokens`（签发）。Firefly **没有**列出和撤销个人访问令牌的 API——原来那是 Passport 的网页路由，随前端一起删了。

需要在 Firefly 侧补两个端点，读写 `oauth_access_tokens` 表：

- `GET /api/v1/tokens` — 列出当前用户的有效令牌（名称、创建时间、到期时间、是否为当前会话）
- `DELETE /api/v1/tokens/{id}` — 撤销

工作量是一个控制器加两个方法。改密码和 2FA 继续走 artisan 命令，不做界面。

## 二、信息架构（已定：IA-3 工作流优先）

一级导航六项：

```
今天    ← 首页，待办 + 今日流水
交易
账户
预算    ← 含「订阅」tab
分析    ← 原报表 + 净资产曲线
设置
```

**账单收件箱和按天对账不占一级入口**，它们是从「今天」进的二级页面：

- 收件箱内容重（渠道卡、任务列表、行审阅、凭证面板），保留独立路由 `/inbox`。
- 对账保留独立路由 `/reconciliation`。
- 两者的入口在「今天」的待办区，侧栏「今天」上挂待办数徽标。
- Cmd+K 里两者都能直达。

原来的「总览」页不再存在，净资产、余额趋势这些全局指标下沉到「分析」。

## 三、首屏行为（已定）

「今天」页的主区**跟着状态走**，不是固定布局：

- **待办区有内容时**：显示待办（待审账单 N 笔 / 等解压密码 M 个 / 未对账 K 天 / 本月待付订阅 J 笔），这是首屏的主体。
- **待办清空后**：主区自动换成「本月还能花多少」——大数字 + 进度条 + 剩余天数。

换句话说，界面在催你干活；活干完了它就告诉你花钱的余量。两种状态之间的切换要有过渡，不能突兀地跳。

依赖：第二种状态需要预算数据。预算没配的时候要有一个"去设个预算"的引导，而不是显示 0。

## 四、视觉（已定）

| 项 | 决定 |
|---|---|
| 收支配色 | **C-A 支付宝向**：收入红、支出中性、转账蓝。对齐支付宝的既有心智，避开「绿=跌」的股市联想。 |
| 非色觉通道 | 金额永远带 `+`/`-`，类型永远有文字或胶囊标签。颜色只是辅助。 |
| 交易行高 | **40px 默认**（Carbon md 档），设置里可切 48px。32px 废弃——放不下复选框，不满足 WCAG 2.2 的 24×24 触控下限。 |
| 深浅主题 | 跟随系统，设置里可手动锁定，存进 preferences。 |
| 金额字体 | 系统等宽（macOS 上是 SF Mono），强制 `tabular-nums`。视觉定稿后再评估要不要换自托管 Inter。 |
| 动效 | 留 GSAP（列表入场、图表揭示）和 Lottie（空状态）。**砍掉 matter.js**（谷粒彩蛋）和 **lenis**（报表页平滑滚动）——各自一个依赖只服务一个场景。 |
| 品牌主色 | **炭墨无彩色**：浅色 `#2B2A24`，深色 `#EDEBE1`。屏幕上只有金额有颜色。 |

### 语义色板（定稿）

红色原本被两件事同时占用——「收入」和「出问题了」。解法是把警示交给琥珀，深红只留给破坏性操作。
这样金额上的红永远意味着进账，按钮上的红永远意味着危险，不会串。绿色只表示「这件事做完了」，不碰金额。

| 语义 | 浅色 | 深色 | 用在哪 | 非色觉通道 |
|---|---|---|---|---|
| 收入 | `#D0402F` | `#F08475` | 金额、收入汇总 | `+` 前缀 |
| 支出 | `#26251F` | `#E6E3D9` | 金额（用正文色，不上色） | `-` 前缀 |
| 转账 | `#2C6BD6` | `#7BA6EA` | 金额、类型标签 | 「转」标签 |
| 需要注意 | `#B0700F` | `#DFA94A` | 待分类、对账差异、待解压密码、超预算 | 图标 + 文案 |
| 危险 | `#8E241A` | `#D2604F` | 只用于删除类按钮与确认框 | 确认框 + 输入名称 |
| 已完成 | `#2C6B4C` | `#63A886` | 已对账、已入账 | 对勾图标 |
| 品牌主色 | `#2B2A24` | `#EDEBE1` | 侧栏选中、主按钮、焦点环、进度条 | — |

主色是无彩色，深浅两个主题下是「近黑」与「近白」的翻转，不是同一个色值调明度。

### 金额排版规则（照 Polaris / Ant Design）

- 明细表里的金额永不缩写，完整千分位；`1.2万` 只出现在图表轴和 KPI 副标签。
- 负号在货币符号前：`-¥32.00`，不是 `¥-32.00`。
- 同列小数位固定两位，零写 `¥0.00`，无数据写 `--`。
- 金额右对齐，文本左对齐，表头与列同向，不要居中表头。

## 五、要补的交易页能力

现在只有四个类型 tab，其余全缺：

1. **筛选栏**：账户、分类、标签、金额区间、关键词。前端把条件编译成 Firefly 的查询语言（`amount:>100 category:餐饮`），走 `/search/transactions`，不用新接口。筛选状态进 URL。
2. **批量选择 + 批量改**：`POST /data/bulk/transactions` 已经在，能批量改分类/预算/标签。
3. **键盘层**：`↑↓` 移动、`Enter` 展开、`C` 改分类、`E` 编辑、`X` 选中。键位抄 Copilot 网页版（官方文档验证过）。
4. **粘性日期头**：分组头 sticky 在顶栏下方。
5. **隐私模式**：`Ctrl+P` 把金额换成 `••••`。

## 六、代码层改动顺序

1. **Token 层**（`styles/tokens.css`）：重写成中性分层（Carbon 式"抬升=表面变浅"）+ 语义色 + 品牌色三组。组件一律通过 token，禁止 `'rgb(220 38 38 / 1)'` 这种字面量。
2. **MoneyText**：改成只接受语义（income/expense/transfer/neutral），强制符号与 tabular-nums，隐私模式在这一个组件里生效。
3. **DataTable**：自建（列定义 + 密度 + 粘性头 + 选择 + 键盘）。不引 TanStack Table——我们的表都是服务端分页，用不上它的客户端排序过滤。
4. **buildFireflyQuery()**：筛选条件 → 查询语言。
5. **日期范围拆页**：每页自己的默认粒度，全局只存上次偏好。
6. **useListKeyboard**：交易页与收件箱共用。
7. **图表**：保留 d3 自绘那套。补主题切换重读 CSS 变量、深色下网格线降到白 6–10%、只保留水平网格、零线加粗、tooltip 显示完整金额。

### 不做的

- 不引组件库成品皮肤。tailwind-plus 继续当组件参考，视觉层走自己的 token。
- 不做主题编辑器。
- 不换状态管理。zustand + React Query 现在的分工是对的。

## 八、改名：Abaku / 算珠

原名「谷仓 / Granary」弃用。理由是占用不干净：中文「谷仓」在国内第一联想是谷仓海外仓 GoodCang（第 9 类软件已有注册），
英文 Granary 在 npm、PyPI、GitHub 上均被占（snarfed/granary、Speakeasy granary、Granary Finance）。

**新名：Abaku / 算珠**。取自希腊语 ἄβαξ（abax，算板，abacus 的词根）。

占用实测（2026-08-05，npm registry / PyPI JSON API / GitHub REST / Verisign RDAP）：
npm 空、PyPI 空、GitHub 用户名已占、`.com` 已占、同名仓库 201 个。
选它是明知 `.com` 被占的取舍——自托管系统不需要域名，真正会天天碰到的是包名，而包名是空的。

顺带一提，实测发现 41 个「读起来像个词」的五字母候选里，`.com` 无一空闲。只有刻意拧过的组合
（`tofku` / `qiksu` / `lopku` / `weksu`）才是全空的。

### 标志

算盘的一根档：一根竖杆、一道横梁、梁上一颗、梁下两颗。**横梁不能省**——没有它，竖杆加珠子会被读成竖向滑块。

矢量源文件在 `docs/design/brand/`：

| 文件 | 用途 |
|---|---|
| `abaku-mark.svg` | 主标志，24×24，用 `currentColor` |
| `abaku-mark-16.svg` | 16px 专用简化稿（favicon / 折叠侧栏）。珠子减到两颗，笔画对齐 16 网格。**不要把主标志缩到 16px** |
| `abaku-appicon.svg` | 应用图标 1024×1024，直角正方形，圆角交给系统 |

字标是「Abaku」在上、「算珠」在下，中文放大字距。用系统字体栈直接排，不做成 SVG——
自托管一个 CJK 字体只为一个字标不值得。

### 改名要动的地方

- 仓库 `firefly-ai-accounting` → `abaku`，前端目录 `granary-web` → `abaku-web`（**用户已确认仓库一起改**）
- `package.json` 的 `name`、`index.html` 的 `<title>`、`public/favicon.svg`（现在还是 Vite 默认的紫色闪电）
- 侧栏字标（现在是 indigo 方块里写「谷」字）
- `compose.yml` 服务名、`Makefile` 的 `WEB_DIR`、nginx 配置、Dockerfile
- 本地 remote URL 与 CI 配置

**存储键 `granary.*` 先不动**（sessionStorage 的令牌、Firefly preferences 里的 `granary.date_range`）。
单独为了改名把本地令牌和服务端偏好清掉不划算，等有别的破坏性变更时一起迁。
